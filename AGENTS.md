# AGENTS.md

> Leave the repository better than you found it.

This repository is documentation-first. Don't just complete tasks—improve the overall experience. Think like a designer, technical writer, and engineer.

## Creativity

Be creative and thoughtful.

If something can be:
- more beautiful,
- easier to read,
- better organized,
- more intuitive,
- more consistent,
- or more enjoyable to navigate,

improve it.

Aim for a repository that feels polished and intentionally crafted.

## Presentation

Improve the developer experience whenever possible.

You're encouraged to enhance:
- Markdown formatting
- Visual hierarchy
- Layout and spacing
- Tables
- Callouts
- Navigation
- Folder organization
- Naming consistency
- Overall UI/UX of the repository

Small improvements that compound into a better experience are always welcome.

## Repository Hygiene

Keep the repository clean.

- Remove obsolete or duplicate files when safe.
- Organize files and folders logically.
- Avoid unnecessary complexity.
- Don't introduce clutter.

## `.gitignore`

Keep `.gitignore` up to date automatically.

If your changes introduce generated, temporary, cache, editor, OS, or build files, add appropriate ignore rules.

Examples include:
- `.DS_Store`
- `Thumbs.db`
- `.idea/`
- `.vscode/`
- `__pycache__/`
- `*.pyc`
- `*.aux`
- `*.log`
- `*.out`
- `*.fls`
- `*.fdb_latexmk`
- `*.synctex.gz`
- build/cache/temp directories

Only ignore files that should never be committed. Avoid ignoring source files or assets that belong in the repository.

## Final Check

Before finishing, ask yourself:

> "Does this repository look and feel better than it did before I started?"

If the answer is no, keep improving.
